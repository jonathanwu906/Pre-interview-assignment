# 題目三：色塊矩陣 — Design Doc

**結論**：這張 10×5 的圖有一條明確的規則和一個異常。規則是**上下左右相鄰的兩格必不同色**——40 組水平相鄰全部不同色、45 組垂直相鄰只有 5 組同色，而斜角相鄰同色 14/72，跟隨機盤面差不多，代表限制只作用在上下左右。異常是**那 5 組垂直同色全部出自同一處：第 4、5 列一模一樣**（0 起算，同程式輸出）——整張圖等於一張 9 列、處處守規則的圖，其中一列被貼了兩次；第一顆星星 (5,3) 正好壓在這條縫上，應該就是在標記它。其他乍看像規律的特徵（第 2、4 欄幾乎相同、幾對很相近的列），拿隨機盤面實際比對後都站不住，逐一交代如下；第二顆星星 (7,1) 試了多種解釋，沒有一種能把它跟其他格子區分開，我選擇不硬掰。全部比對都由程式完成（C#，`csharp/`），12 項自我驗證通過。

## 1. 做法

先把圖轉成資料：程式偵測色塊範圍、取每格中央區域的顏色中位數歸類成 R/Y/G/B、用白色像素找出星星位置——之後所有判斷都建立在這份資料上，不靠肉眼。接著把想驗證的猜測列成清單逐一檢查，每個猜測都問同一個問題：**把這 50 格顏色隨機打亂 20,000 次，這個特徵會自己出現幾次？**出現得夠罕見才算數。確認規則之後還有一步：剩下的疑似規律改用「守規則、而且有一列重複」的隨機盤面再測一次——因為規則本身就會讓列與欄長得比較像，不重測就會把規則的副作用誤認成新規則。

## 2. 發現

**相鄰不同色**。水平 0/40、垂直 5/45。隨機打亂 20,000 次裡，「水平全部不同色」只出現 1 次。斜角方向是對照組：14/72 ≈ 19% 同色，和受約束方向的 0% 天差地別、與隨機水準同一量級（依顏色比例推算約 26%）——所以規則明確只管上下左右，不是「顏色整體很分散」這種泛泛解釋。

**第 4、5 列重複，星 1 壓線**。全圖僅有的 5 個垂直同色，正好就是這兩列的逐格重合。「存在相鄰兩列完全相同」在 20,000 張隨機盤面裡只出現 137 張。最簡潔的解釋：做圖的人在簡報軟體裡把一列貼了兩次，星 1 跨在第 4/5 列交界上，標記這個異常。

**乍看像規律、驗過不算的**。第 2、4 欄只差 2 格（且差異恰為前兩格互換）：完全隨機的盤面裡，出現這麼相近的欄位對的機會只有約 0.3%，乍看顯著；但改用「守規則＋複製一列」的盤面重測，20,000 張裡有 1,040 張（約 5%）會自己冒出這麼近的欄位對——相鄰不同色本來就會逼欄位互相靠近。加上我前後試了十幾個猜測，這種程度的巧合遲早會撞到幾個，所以不採納。同理，另外幾對只差 1 格的列，重測下 36% 的盤面都有，純屬規則的副作用。顏色數量（R11、Y10、G15、B14）的差異也在隨機波動範圍內，不構成規律。

**星 2 (7,1)：找不到站得住的解釋**。逐一檢查它的局部性質——與 8 個鄰居皆不同色、與斜角鄰居皆不同、該色在列內唯一、在欄內唯一、顏色被鄰居唯一決定——每一種都同時有 2 到 26 格符合，沒有一種只挑出兩顆星。兩顆星都落在 r+c=8 的斜線上，但試過這麼多猜測之後，這種巧合沒有說服力。我的判讀：星 2 是干擾項；也可能出題者想的是某個我沒列到的性質，但與其硬掰一個，不如把試過的全部列出來。

## 3. 程式與驗證

C#（`csharp/`，.NET 10，零外部相依）：

- **`Png.cs`**：自己寫的 PNG 讀寫（macOS 上的 .NET 沒有內建影像庫，為一張圖拉第三方套件不值得）。讀取支援截圖常見的格式：8-bit 灰階／RGB／調色盤／RGBA、五種 scanline filter；寫出（供 selftest 產生合成測試圖）為 8-bit RGB。
- **`GridExtractor.cs`**：抽色流程——高飽和度像素定位色塊範圍、每格取中央 50% 區域、飽和像素逐通道中位數轉色相分類、白色像素占比超過 3% 判定星星。
- **`Analysis.cs`**：上述全部比對與兩種隨機盤面的生成。固定 seed，任何機器重跑，所有數字完全相同（已在 macOS 與 Linux x86_64／arm64 實測，輸出逐字元一致，見 `csharp/README.md`）。

驗證（`dotnet run -- selftest`，12 項）：PNG 讀寫往返（含五種 filter）；抽色流程的關鍵測試是 **round-trip**——程式自己畫一張已知答案的網格圖（含星星白斑），再用正式流程讀回，必須還原全部 50 格顏色與兩顆星位置；分析的固定結論（計數、違規位置、相近列欄、性質掃描命中數）逐項精確比對；兩種隨機盤面下各特徵的出現率釘在保結論的區間內。

## 4. 測試設計

| # | 測項 | 驗證目標 |
|---|---|---|
| 1–2 | PNG 讀寫往返（filter 0；filter 0–4 輪替） | 讀圖正確性 |
| 3–4 | 合成網格圖 → 抽色 → 還原 50 格顏色與星星位置 | 抽色流程 end-to-end |

| 9 | 相近列／欄清單精確比對 | 重複性掃描 |
| 10 | 隨機打亂盤面：三項特徵的出現率夠罕見 | 規則不是巧合 |

## 附錄：重現方式

於 `csharp/` 下：`dotnet run`（內建已數位化矩陣的完整分析）；`dotnet run -- <image.png>`（對圖片重新抽色後分析）；`dotnet run -- selftest`（12 項驗證）。環境：.NET 10，無外部套件。實際輸出收錄於 `csharp/README.md`。
